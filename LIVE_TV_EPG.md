# Live TV / EPG addon support (`behaviorHints.epgProvider`) — findings & design

Status: proposal (2026-07-02). Companion file: [TODO.md](TODO.md) (Home screen / Continue
Watching plan and open questions). Nothing implemented yet; the target addon does not exist
yet either.

Goal: support a future addon type flagged with `behaviorHints.epgProvider: true` that
provides TV channels (id, type, name, logo, deep links) and, per channel, a program of
shows (title, overview, thumbnail, times, genres/cast/directors, deep links). UI target:
a per-date guide grid (channels × time, defaults to today, red now-line), a show modal with
metadata, and a Play button only when the show is currently live. Constraint: **extend, do
not refactor** — follow existing addon conventions except for data format/deeplink deltas.

---

## 1. Codebase findings (verified 2026-07-02, branch `development`, post-0.59.0)

### Architecture

- Message-driven runtime: frontends dispatch `Action`s, models implement
  `UpdateWithCtx<E>` (`src/models/`), async results re-enter as
  `Internal::ResourceRequestResult(ResourceRequest, Result<ResourceResponse, EnvError>)`
  (`src/runtime/msg/internal.rs:145`), changed fields emit `RuntimeEvent::NewState`.
- Aggregate model is generated by `#[derive(Model)]` (`stremio-derive/src/lib.rs`); the web
  bridge is `WebModel` (`stremio-core-web/src/model/model.rs:38`) + one
  `serialize_<model>.rs` per screen (deep links get attached in serializers via
  `stremio-core-web/src/model/deep_links_ext/`).
- Resource machinery (`src/models/common/resource_loadable.rs`):
  `ResourceLoadable<T> { request, content: Option<Loadable<T, ResourceError>> }`;
  `resources_update[_with_vector_content]` plans via `AggrRequest::plan(addons)`, dedupes
  in-flight/loaded requests, converts responses with `T::try_from(ResourceResponse)`.
  Empty vectors → `ResourceError::EmptyContent`.

### Addon layer

- `Manifest` (`src/types/addon/manifest.rs:17`): `types: Vec<String>`,
  `resources: Vec<ManifestResource>`, `id_prefixes`, `catalogs: Vec<ManifestCatalog>`,
  `behavior_hints: ManifestBehaviorHints`.
- `ManifestBehaviorHints` (`manifest.rs:442`): `adult`, `p2p`, `configurable`,
  `configuration_required` — all `bool` + `#[serde(default)]`. **No `#[serde(flatten)]`
  catch-all: unknown hints are silently dropped.** ⇒ an addon can ship
  `epgProvider: true` today; old clients ignore it; adding the field to core is one line
  and fully backward compatible.
- `ManifestCatalog` (`manifest.rs:270`): `id`, `type`, `name?`, flattened
  `extra: ManifestExtra` (`ExtraProp { name, is_required, options, options_limit }`).
  **Catalogs have NO behaviorHints field** — gate EPG behavior at the manifest level, not
  per catalog.
- `ResourceResponse` (`src/types/addon/response.rs:85`), custom deserializer requiring
  exactly one key, invalid array items skipped (`VecSkipError`): `Metas`,
  **`MetasDetailed { metasDetailed: Vec<MetaItem> }`** (full metas incl. videos — the key
  enabler for a one-request guide grid), `Meta`, `Streams`, `Subtitles`, `Addons`.
- `AggrRequest` (`src/types/addon/request.rs:157`): `AllCatalogs`, `CatalogsFiltered`
  (id-list extras like `calendarVideosIds`), `AllOfResource(ResourcePath)` (one request per
  addon whose `manifest.is_resource_supported(path)` — resource name + type + id-prefix).
- Extra-prop constants precedent (`src/constants.rs:102-137`): `SKIP_EXTRA_PROP`,
  `LAST_VIDEOS_IDS_EXTRA_PROP` (`lastVideosIds`), `CALENDAR_IDS_EXTRA_PROP`
  (`calendarVideosIds`).

### Types

- `type` is a **free-form String everywhere** (never an enum). `"tv"` and `"channel"` are
  known only to `TYPE_PRIORITIES` (`src/constants.rs:138`: all=5, movie=4, series=3,
  channel=2, tv=1) used for sort ordering. No live-TV behavior exists anywhere.
- `MetaItemPreview` (`src/types/resource/meta_item.rs:149`): id, type, name, poster,
  background, logo, description, release_info, runtime, released, poster_shape, links,
  trailer_streams, behavior_hints. Channels need nothing more.
- `MetaItem` (`meta_item.rs:244`) = flattened preview + `videos: Vec<Video>`.
- `Video` (`meta_item.rs:329`): `id`, `title` (alias `name`), `released:
  Option<DateTime<Utc>>`, `overview`, `thumbnail`, `streams` (alias `stream`, OneOrMany),
  flattened `series_info: Option<SeriesInfo>` (precedent for flattened optional groups),
  `trailer_streams`. **No behaviorHints, no start/end times, no genres/cast.**
- `MetaItemBehaviorHints.has_scheduled_videos: bool` (`meta_item.rs:429`) exists (serde
  round-trip tested) but **nothing in core consumes it** — it was designed for exactly
  this scheduled-channel case; frontends use it for the "upcoming schedule" video list.
- Deep links (`src/deep_links/mod.rs`): `VideoDeepLinks` (meta_details_videos,
  meta_details_streams, player, external_player) built via
  `From<(&Video, &ResourceRequest, &Option<Url>, &Settings)>` (line ~397);
  `CalendarDeepLinks` → `stremio:///calendar/{year}/{month}` (line ~704) is the pattern
  for a new screen deep link. URI shapes: `stremio:///detail/{type}/{id}[/{video_id}]`,
  `stremio:///player/{encoded_stream}[/...]`.

### Models to pattern-match

- `Calendar` (`src/models/calendar.rs`) — closest structural precedent: fetch metas via
  `AggrRequest`, then pure `items_update` derives date-bucketed
  `ContentItem { meta_item, video }` in core; `selected` defaults to now via `E::now()`;
  prev/next in `Selectable`.
- `CatalogWithFilters<T>` (`src/models/catalog_with_filters.rs`) — `Selectable` pattern:
  every filter option carries a ready-to-dispatch `ResourceRequest`; `next_page` only if
  catalog declares `skip`; extras toggled via `ExtraExt::extend_one`.
- `MetaDetails` (`src/models/meta_details.rs`) — `AllOfResource` for meta + streams;
  streams either embedded in `Video.streams` or fetched from `stream` resource addons.
- `ContinueWatchingPreview` (`src/models/continue_watching_preview.rs`) +
  `LibraryItem::is_in_continue_watching()` (`src/types/library/library_item.rs:52`):
  `type != "other" && (!removed || temp) && state.time_offset > 0`. ⇒ **played channels
  will leak into Continue Watching automatically** (Player writes temp library items with
  time_offset) — see [TODO.md](TODO.md).

### New-model checklist (how anything gets exposed)

1. `src/models/<name>.rs` implementing `UpdateWithCtx<E>`; register in `src/models/mod.rs`.
2. `ActionLoad::<Name>(Selected)` variant in `src/runtime/msg/action.rs` (+ per-model
   action enum if needed).
3. Field on `WebModel` (`stremio-core-web/src/model/model.rs`) — derive macro wires it.
4. `serialize_<name>.rs` + match arm in `WebModel::get_state` + init in `WebModel::new`.

## 2. Proposed addon contract

Manifest — a standard addon plus one hint:

```json
{
  "id": "org.example.puretv",
  "types": ["tv"],
  "resources": ["catalog", "meta", "stream"],
  "idPrefixes": ["puretv:"],
  "behaviorHints": { "epgProvider": true },
  "catalogs": [{
    "id": "puretv-guide", "type": "tv", "name": "PureTV",
    "extra": [{ "name": "date" }, { "name": "skip" }]
  }]
}
```

- **Guide**: `catalog/tv/{catalogId}/date=YYYY-MM-DD.json` → `{ "metasDetailed": [...] }`.
  Each entry = one channel (`MetaItemPreview`: `id`, `type: "tv"`, `name`, `logo`) with
  `videos` = that date's shows. One request per addon for the whole grid; `skip` extra
  paginates long channel lists. Core always sends `date` (defaulting to today) —
  `epgProvider: true` implies the catalog supports it; the addon should still default to
  today defensively if `date` is ever absent.
- **Shows are `Video`s**, not metas. Show ids prefixed by channel id
  (`puretv:axn:2026-07-02T11:55`). Addons should also set `released = startTime` so
  Calendar/notifications/stremio-web schedule UIs work unmodified.
- **Channel meta** (optional but recommended): `meta/tv/{channelId}.json` returns the
  channel `MetaItem` with `behaviorHints.hasScheduledVideos: true` and a multi-day program
  in `videos` — makes the existing MetaDetails page work for free (shared links, search).
- **Streams**: the live show's `Video.streams` carries the channel live stream, and/or the
  addon serves `stream/tv/{videoId}` — both paths already flow through
  MetaDetails/Player untouched.

## 3. Core changes (purely additive)

1. `ManifestBehaviorHints.epg_provider: bool` `#[serde(default)]`
   (`src/types/addon/manifest.rs:442`) + serde test
   (`src/unit_tests/serde/manifest_behavior_hints.rs`).
2. `EPG_DATE_EXTRA_PROP` (`name: "date"`) in `src/constants.rs`, next to
   `CALENDAR_IDS_EXTRA_PROP`.
3. Extend `Video` with a flattened optional group (mirrors `series_info`; `None` for all
   existing addons ⇒ zero impact):

   ```rust
   #[serde(default, flatten)]
   pub epg_info: Option<VideoEpgInfo>,

   #[serde(rename_all = "camelCase")]
   pub struct VideoEpgInfo {
       pub start_time: DateTime<Utc>,
       pub end_time: DateTime<Utc>,
       pub runtime: Option<String>,
       pub release_info: Option<String>,
       pub genres: Vec<String>,      // could alternatively be Link-based like MetaItemPreview
       pub cast: Vec<String>,
       pub directors: Vec<String>,
       pub links: Vec<Link>,
   }
   ```

   `Some(epg_info)` is the "this is a program show" marker; add
   `VideoEpgInfo::is_live(now: DateTime<Utc>) -> bool` (start ≤ now < end).
4. New model `LiveTvGuide` (`src/models/live_tv_guide.rs`) — Calendar × CatalogWithFilters
   hybrid:
   - `Selected { catalog: Option<ResourceRequest>, date: Option<NaiveDate> }`; date
     defaults to today via `E::now()`.
   - `Selectable { catalogs, types, prev_date, next_date, next_page }` built **only from
     addons with `manifest.behavior_hints.epg_provider`** (this is the hint's entire job);
     each option carries a ready `ResourceRequest` (CatalogWithFilters pattern).
   - Loads with `resource_update_with_vector_content::<E, Vec<MetaItem>>` after
     `extend_one(&EPG_DATE_EXTRA_PROP, date)`; `TryFrom<ResourceResponse>` already accepts
     `MetasDetailed`. The `date` extra is appended **unconditionally** for epgProvider
     addons (`Selected.date`, else today via `E::now()`) — `epgProvider: true` implies
     `date` support, the catalog does not need to declare it (see §5).
   - Derives `channels: Vec<ChannelGuide { channel: MetaItemPreview, shows: Vec<Video>
     (sorted by start_time), deep_links }>` in core (Calendar `items_update` pattern).
   - `ActionLoad::LiveTvGuide(Selected)` variant.
5. `LiveTvDeepLinks { live_tv: String }` → `stremio:///livetv/{date}` in
   `src/deep_links/mod.rs` (CalendarDeepLinks clone). Shows reuse existing
   `VideoDeepLinks` — its `player`/`external_player` links are the modal's Play button.
6. Web bridge: `live_tv_guide` field on `WebModel` + `serialize_live_tv_guide.rs`; the
   serializer attaches per-show `deepLinks` and computed `isLive: bool` (frontend's only
   Play-button logic is reading that flag).

No existing code paths change: new optional fields, one constant, one model file, one enum
variant, one deep-link struct, one serializer.

## 4. UI mapping

- **Grid screen**: `LiveTvGuide` for today → rows = `channels`, blocks positioned by
  `startTime`/`endTime` (UTC from core; now-line and pixel math are frontend concerns).
  Channel/provider dropdowns and day arrows come from `Selectable`.
- **Show modal**: rendered from the `Video` already in state (overview, runtime,
  releaseInfo, genres, cast) — no extra fetch. Play iff `isLive`, via `deepLinks.player`.

## 5. Prior art: mrcanelas/pure-tv-addon (reviewed 2026-07-02)

Existing community addon (M3U playlist + XMLTV → stremio-addon-sdk) that already ships
`behaviorHints.epgProvider: true`. Validates most of this proposal, diverges on fetch
topology:

- **Matches**: manifest hint name/placement; `tv` type + catalog/meta/stream + idPrefix;
  shows as `Video`s with flat `startTime`/`endTime` (ISO strings), `runtime`, `genres`,
  `cast`, `directors`, `overview`, `thumbnail`, `links` — parses as-is with the proposed
  flattened `VideoEpgInfo`; channel-prefixed show ids (`pure:{ch}:{prog}`) with the stream
  handler resolving any show id to the channel live stream; `skip` pagination (20/page);
  cacheMaxAge + stale-while-revalidate headers.
- **Diverges**: catalog returns bare channel previews (`metas`, no videos, **no `date`
  extra**) — all program data via per-channel `meta`, which returns the FULL multi-day
  XMLTV window (client filters by day). `released` = XMLTV original air date (drives the
  modal's year), NOT startTime. No `hasScheduledVideos` on channel metas. `links` target
  search, not Discover. Extra `subtitle` field on videos (unmodeled). Bug: programs
  missing XMLTV `date` throw (`new Date(undefined).toISOString()`) → 500s the meta.
- **Direction (decided 2026-07-02): the addon follows core, not the reverse** — fixes for
  this addon are in [PURE_TV_ADDON_ALIGNMENT.md](PURE_TV_ADDON_ALIGNMENT.md). Core keeps
  `catalog` → `metasDetailed` as the hard contract (a plain `Metas` response cannot feed
  the grid; no per-channel meta fan-out in `LiveTvGuide`).
- **`epgProvider: true` implies `date` support — core always sends a concrete date.**
  `LiveTvGuide` appends the `date` extra to every guide catalog request toward
  epgProvider addons regardless of the catalog's declared extras (the manifest hint, not
  the extra declaration, is the capability signal): `Selected.date` when set, otherwise
  today via `E::now()`. Addons must honor it (and should default to today themselves as a
  defensive measure). Core still buckets videos by the selected day client-side for
  midnight-spanning shows (Calendar `items_update` precedent). Declaring `date` in the
  catalog's `extra` list stays recommended for documentation/other clients, but is not
  what core keys on.

## 6. Deliberate decisions & alternatives rejected

- **Guide via catalog `metasDetailed`, not per-channel `meta`**: one round-trip per page
  vs N channel requests. Per-channel meta means N `ResourceLoadable`s, N loading states,
  N `NewState` ticks, rows popping in out of order, and browser connection throttling on
  cold load; one catalog page is an atomic snapshot with one cache entry per
  `(catalog, date, skip)` URL (CDN-friendly — everyone asks for the same date).
  Per-channel `meta` remains the source for a full multi-day single-channel program
  (depth), while catalog pages serve the grid (breadth, one date).
- **1000+ channels**: never one response (~10–50 KB/channel/day ⇒ tens of MB). Handled by
  (a) the `skip` extra — pages of 50–100 channels (~1–5 MB), lazy-loaded on scroll
  (Discover `next_page` / `CatalogsWithExtra::LoadRange` precedents), which also bounds
  core state size and serialization cost; and (b) `genre`-style slicing extras (country/
  category/package) so users browse a subset, matching the guide's dropdown UI. The
  per-channel alternative at this scale is worse: ~15 requests per viewport, re-fired on
  every scroll step.
- **Gate on manifest hint, not catalog-level hint**: catalogs have no behaviorHints field
  and adding one would touch core deserialization more broadly.
- **`VideoEpgInfo` flatten vs adding a `Video.behavior_hints`**: flatten matches the
  existing `series_info` precedent and keeps show fields typed.
- **Reusing `released` alone (hasScheduledVideos convention) rejected**: an EPG needs an
  explicit end time; `released = startTime` is kept as a compat convention instead.
- **`CatalogWithFilters<MetaItem>` reuse rejected**: fetching would nearly work via the
  generic adapter, but epgProvider-only addon filtering, date defaulting, and derived
  time-bucketed state justify a dedicated model with zero refactor.
- Home screen / Continue Watching strategy and open questions (cache-until-endTime
  refresh, timezone of `date`, channel MetaDetails): see [TODO.md](TODO.md).
